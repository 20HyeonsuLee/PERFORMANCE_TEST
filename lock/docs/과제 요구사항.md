## 과제: 실시간 베팅 시스템

### 배경

점심시간에 여러 메뉴에 대해 동시에 베팅이 진행되는 시스템

- 10개 베팅방이 동시 운영
- 각 방마다 최소 5명 모이면 게임 시작
- 100명의 사용자가 동시에 랜덤하게 베팅

---

## 핵심 요구사항

### 기능

1. **베팅하기**: 특정 방에 금액을 베팅
2. **게임 시작 대기**: 최소 인원 모일 때까지 대기
3. **실시간 통계**: 각 방의 현황 조회 (참가자 수, 총 베팅금액)
4. **전체 통계**: 모든 방의 합계

### 제약사항

- 동시에 100개 스레드가 동작
- 베팅은 원자적으로 처리 (중복/누락 불가)
- 최소 인원 체크는 정확해야 함 (5명 미만에 시작 안 됨)
- 통계는 항상 정확한 값

---

## Phase 1: 문제 있는 버전

### 구현 방향

- **모든 메서드를 전역 synchronized로**
- **최소 인원 대기를 while문 + sleep으로** (wait 사용 금지)
- **모든 베팅방을 하나의 락으로 관리**

### 기대 결과 (문제점 발견)

- [ ]  "서울 날씨" 방에 베팅하는데 "부산 날씨" 방도 블로킹되는가?
- [ ]  CPU 사용률이 높은가?
- [ ]  100개 스레드가 1000번씩 베팅할 때 몇 초 걸리는가?

### 질문

1. 왜 다른 방인데 서로 막히는가?
2. CPU를 왜 많이 쓰는가?
3. 성능이 안 나오는 진짜 원인은?

## Phase 2: 개선 버전

### 구현 방향

- **베팅방마다 독립적인 락**
- **wait/notify로 최소 인원 대기** (busy waiting 제거)
- **notify vs notifyAll 둘 다 테스트**

### 기대 결과 (개선 확인)

- [ ]  다른 방끼리는 동시 처리되는가?
- [ ]  CPU 사용률이 낮아졌는가?
- [ ]  Phase 1 대비 몇 배 빨라졌는가?
- [ ]  notify 썼을 때 문제가 생기는가?

### 실험

**시나리오 A**: notify() 사용

- 5명이 대기 중
- 1명이 베팅 → notify() 호출
- 몇 명이 깨어나는가?
- 게임이 시작되는가?

**시나리오 B**: notifyAll() 사용

- 5명이 대기 중
- 1명이 베팅 → notifyAll() 호출
- 몇 명이 깨어나는가?
- 게임이 시작되는가?

### 질문

1. notify로 충분한 경우가 있는가?
2. notifyAll이 필수인 경우는?
3. 락 범위를 더 줄일 수 있는가?

# SSE 메트릭 가이드

Micrometer를 사용한 SSE 성능 메트릭 자동 수집

## 수집되는 메트릭

### 메시지 메트릭

#### `sse.messages.sent` (Counter)
- **설명**: 전송에 성공한 SSE 메시지 총 개수
- **타입**: Counter (누적)
- **단위**: 개
- **수집 위치**: SseService.sendMessage()

#### `sse.messages.failed` (Counter)
- **설명**: 전송에 실패한 SSE 메시지 총 개수
- **타입**: Counter (누적)
- **단위**: 개
- **수집 위치**: SseService.sendMessage() - IOException 발생 시

#### `sse.broadcast.duration` (Timer)
- **설명**: 모든 클라이언트에게 메시지를 브로드캐스트하는데 걸린 시간
- **타입**: Timer
- **단위**: 밀리초
- **제공 통계**:
  - count: 총 브로드캐스트 횟수
  - sum: 총 소요 시간
  - mean: 평균 소요 시간
  - max: 최대 소요 시간
  - percentiles: P50, P75, P95, P99
- **수집 위치**: SseService.broadcastToAll()

### 연결 메트릭

#### `sse.connections.active` (Gauge)
- **설명**: 현재 활성화된 SSE 연결 수
- **타입**: Gauge (실시간 값)
- **단위**: 개
- **수집 위치**: SseController - emitters Map 사이즈

#### `sse.connections.total` (Counter)
- **설명**: 누적 SSE 연결 시도 총 개수
- **타입**: Counter (누적)
- **단위**: 개
- **수집 위치**: SseController.stream() - 연결 성공 시

#### `sse.connections.errors` (Counter)
- **설명**: SSE 연결 오류 총 개수
- **타입**: Counter (누적)
- **단위**: 개
- **수집 위치**: SseController - onError, 초기 메시지 전송 실패 시

## 메트릭 확인 방법

### 1. Actuator Endpoint

#### 모든 메트릭 확인
```bash
curl http://localhost:8080/actuator/metrics
```

#### 특정 메트릭 상세 확인
```bash
# 전송된 메시지 수
curl http://localhost:8080/actuator/metrics/sse.messages.sent

# 실패한 메시지 수
curl http://localhost:8080/actuator/metrics/sse.messages.failed

# 브로드캐스트 소요 시간
curl http://localhost:8080/actuator/metrics/sse.broadcast.duration

# 활성 연결 수
curl http://localhost:8080/actuator/metrics/sse.connections.active

# 총 연결 수
curl http://localhost:8080/actuator/metrics/sse.connections.total

# 연결 오류 수
curl http://localhost:8080/actuator/metrics/sse.connections.errors
```

### 2. Prometheus Endpoint

Spring Boot Actuator와 Micrometer가 활성화되어 있으면 Prometheus 형식으로 메트릭을 노출합니다.

```bash
curl http://localhost:8080/actuator/prometheus | grep sse
```

출력 예시:
```
# HELP sse_messages_sent_total Total number of SSE messages sent
# TYPE sse_messages_sent_total counter
sse_messages_sent_total 15420.0

# HELP sse_messages_failed_total Total number of SSE messages failed to send
# TYPE sse_messages_failed_total counter
sse_messages_failed_total 3.0

# HELP sse_broadcast_duration_seconds Time taken to broadcast messages to all clients
# TYPE sse_broadcast_duration_seconds summary
sse_broadcast_duration_seconds_count 1542.0
sse_broadcast_duration_seconds_sum 24.567
sse_broadcast_duration_seconds_max 0.089

# HELP sse_connections_active Current number of active SSE connections
# TYPE sse_connections_active gauge
sse_connections_active 100.0

# HELP sse_connections_total_total Total number of SSE connections
# TYPE sse_connections_total_total counter
sse_connections_total_total 125.0

# HELP sse_connections_errors_total Total number of SSE connection errors
# TYPE sse_connections_errors_total counter
sse_connections_errors_total 2.0
```

## 메트릭 분석 예시

### 메시지 전송 성공률 계산
```
성공률 = (sse.messages.sent / (sse.messages.sent + sse.messages.failed)) * 100
```

예: 15420 / (15420 + 3) * 100 = 99.98%

### 연결 성공률 계산
```
성공률 = ((sse.connections.total - sse.connections.errors) / sse.connections.total) * 100
```

예: (125 - 2) / 125 * 100 = 98.4%

### 평균 브로드캐스트 시간
```
평균 시간 = sse.broadcast.duration (mean)
```

### 클라이언트당 평균 처리 시간
```
클라이언트당 시간 = sse.broadcast.duration.mean / sse.connections.active
```

예: 24ms / 100 = 0.24ms per client

## Prometheus + Grafana 연동

### 1. Prometheus 설정

`prometheus.yml`:
```yaml
scrape_configs:
  - job_name: 'spring-boot-sse'
    metrics_path: '/actuator/prometheus'
    scrape_interval: 5s
    static_configs:
      - targets: ['localhost:8080']
```

### 2. Grafana 대시보드

#### 메시지 전송 패널
- **메트릭**: `rate(sse_messages_sent_total[1m])`
- **설명**: 초당 전송된 메시지 수 (TPS)
- **차트**: Time series

#### 메시지 실패율 패널
- **메트릭**: `rate(sse_messages_failed_total[1m]) / rate(sse_messages_sent_total[1m]) * 100`
- **설명**: 메시지 실패율 (%)
- **차트**: Time series

#### 활성 연결 패널
- **메트릭**: `sse_connections_active`
- **설명**: 현재 활성 SSE 연결 수
- **차트**: Gauge

#### 브로드캐스트 지연시간 패널
- **메트릭**:
  - P50: `sse_broadcast_duration_seconds{quantile="0.5"}`
  - P95: `sse_broadcast_duration_seconds{quantile="0.95"}`
  - P99: `sse_broadcast_duration_seconds{quantile="0.99"}`
- **설명**: 브로드캐스트 소요 시간 분포
- **차트**: Time series (multiple series)

#### 연결 성공률 패널
- **메트릭**: `(increase(sse_connections_total_total[5m]) - increase(sse_connections_errors_total[5m])) / increase(sse_connections_total_total[5m]) * 100`
- **설명**: 최근 5분간 연결 성공률 (%)
- **차트**: Stat

## k6 테스트와 메트릭 비교

### k6 메트릭 (클라이언트 관점)
- `sse_messages_received`: 클라이언트가 수신한 메시지 수
- `sse_message_latency`: 메시지 출발(서버 timestamp) → 도착(클라이언트) 지연시간
- `sse_connection_success`: 클라이언트 연결 성공률

### Micrometer 메트릭 (서버 관점)
- `sse.messages.sent`: 서버가 전송한 메시지 수
- `sse.broadcast.duration`: 서버 내부 브로드캐스트 처리 시간
- `sse.connections.active`: 서버가 관리하는 활성 연결 수

### 비교 분석

#### 메시지 손실률
```
손실률 = (sse.messages.sent - k6.sse_messages_received) / sse.messages.sent * 100
```

서버는 10,000개 전송했는데 클라이언트가 9,950개만 수신했다면:
- 손실률 = (10000 - 9950) / 10000 * 100 = 0.5%

#### 전체 지연시간 분석
- **서버 처리 시간**: `sse.broadcast.duration` (서버 내부 처리)
- **네트워크 + 클라이언트 시간**: `sse_message_latency - sse.broadcast.duration`

예:
- 브로드캐스트 처리: 15ms (서버 메트릭)
- 전체 지연시간: 48ms (k6 메트릭)
- 네트워크 지연: 48 - 15 = 33ms

## 알림 설정 (Prometheus Alerting)

### 높은 메시지 실패율
```yaml
- alert: HighSSEMessageFailureRate
  expr: rate(sse_messages_failed_total[5m]) / rate(sse_messages_sent_total[5m]) > 0.01
  for: 2m
  annotations:
    summary: "SSE 메시지 실패율이 1%를 초과했습니다"
```

### 브로드캐스트 지연 증가
```yaml
- alert: SlowSSEBroadcast
  expr: histogram_quantile(0.95, rate(sse_broadcast_duration_seconds_bucket[5m])) > 0.1
  for: 3m
  annotations:
    summary: "SSE 브로드캐스트 P95 지연시간이 100ms를 초과했습니다"
```

### 연결 오류 급증
```yaml
- alert: HighSSEConnectionErrors
  expr: rate(sse_connections_errors_total[5m]) > 1
  for: 2m
  annotations:
    summary: "SSE 연결 오류가 분당 1건 이상 발생하고 있습니다"
```

## 메트릭 보존 및 성능

### Micrometer 기본 설정

메트릭은 메모리에 저장되며 영향이 미미합니다:
- Counter: ~40 bytes
- Timer: ~1KB (히스토그램 포함)
- Gauge: ~40 bytes

100개의 메트릭이라도 총 메모리 사용량 < 1MB

### Prometheus 스크랩

권장 설정:
- `scrape_interval`: 5-15초
- 너무 짧으면 네트워크 오버헤드 증가
- 너무 길면 실시간성 저하

## 문제 해결

### 메트릭이 보이지 않는 경우

1. Actuator 엔드포인트 활성화 확인:
```yaml
# application.yml
management:
  endpoints:
    web:
      exposure:
        include: health,info,metrics,prometheus
```

2. Micrometer 의존성 확인:
```kotlin
// build.gradle.kts
implementation("org.springframework.boot:spring-boot-starter-actuator")
implementation("io.micrometer:micrometer-registry-prometheus")
```

3. 메트릭 수집 확인:
```bash
# 로그에서 확인
grep "sse.messages.sent" application.log

# 또는 직접 요청
curl http://localhost:8080/actuator/metrics | grep sse
```

### 메트릭 값이 이상한 경우

- **Counter가 감소**: Counter는 누적값이므로 감소하지 않음. 애플리케이션 재시작 시 0으로 리셋
- **Gauge가 0**: emitters Map이 비어있음. SSE 연결이 없는 상태
- **Timer 값이 너무 큼**: 브로드캐스트 중 많은 클라이언트에게 전송 중이거나 네트워크 지연

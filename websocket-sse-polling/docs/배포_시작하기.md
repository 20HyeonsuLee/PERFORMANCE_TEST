# 배포 시작하기

이 가이드는 WebSocket-SSE-Polling 모듈을 GitHub Actions를 통해 자동 배포하는 방법을 안내합니다.

## 사전 준비

### 1. GitHub Secrets 설정

GitHub 저장소 → Settings → Secrets and variables → Actions → New repository secret

다음 secrets를 추가하세요:

```
DOCKER_HUB_USERNAME=your-dockerhub-username
DOCKER_HUB_TOKEN=your-dockerhub-token
SERVER_HOST=your-server-ip
SERVER_USER=ubuntu
SSH_PRIVATE_KEY=your-ssh-private-key
SLACK_WEBHOOK_URL=your-slack-webhook-url (선택사항)
```

### 2. Docker Hub 토큰 생성

1. [Docker Hub](https://hub.docker.com/) 로그인
2. Account Settings → Security → New Access Token
3. 생성된 토큰을 `DOCKER_HUB_TOKEN`에 저장

### 3. SSH 키 생성

```bash
# 로컬에서 SSH 키 생성
ssh-keygen -t rsa -b 4096 -C "github-actions" -f ~/.ssh/github-actions

# 공개키를 서버에 복사
ssh-copy-id -i ~/.ssh/github-actions.pub user@your-server

# 개인키 내용을 복사하여 GitHub Secret에 저장
cat ~/.ssh/github-actions
```

## 서버 설정

### 1. 서버 접속 및 Docker 설치

```bash
ssh user@your-server

# Docker 설치
sudo apt-get update
sudo apt-get install -y docker.io docker-compose

# Docker 사용자 권한 설정
sudo usermod -aG docker $USER

# 로그아웃 후 다시 로그인
exit
ssh user@your-server
```

### 2. 애플리케이션 디렉토리 생성

```bash
# 애플리케이션 디렉토리 생성
sudo mkdir -p /opt/websocket-sse-polling
sudo chown $USER:$USER /opt/websocket-sse-polling
cd /opt/websocket-sse-polling

# 로그 디렉토리 생성
mkdir -p logs
```

### 3. docker-compose.yml 파일 생성

```bash
# websocket-sse-polling/docker-compose.yml 파일 내용을 서버에 복사
nano docker-compose.yml
```

### 4. 환경 변수 파일 생성

```bash
# .env 파일 생성
nano .env
```

`.env` 파일 내용:
```env
SPRING_PROFILES_ACTIVE=prod
SERVER_PORT=8080
LOG_LEVEL=INFO
DOCKER_HUB_USERNAME=your-dockerhub-username
```

## 배포 실행

### 자동 배포

1. 코드 수정 후 `main` 브랜치에 push:
```bash
git add .
git commit -m "feat: add new feature"
git push origin main
```

2. GitHub Actions 탭에서 배포 진행 상황 확인

### 수동 배포

1. GitHub 저장소 → Actions → Deploy WebSocket-SSE-Polling
2. "Run workflow" 클릭
3. 환경 선택 (dev/prod)
4. "Run workflow" 버튼 클릭

## 배포 확인

### 1. 서버에서 컨테이너 상태 확인

```bash
ssh user@your-server
cd /opt/websocket-sse-polling

# 컨테이너 상태 확인
docker ps

# 로그 확인
docker logs -f websocket-sse-polling
```

### 2. Health Check

```bash
curl http://your-server:8080/actuator/health
```

응답 예시:
```json
{
  "status": "UP"
}
```

### 3. 메트릭 확인

```bash
# 기본 메트릭
curl http://your-server:8080/actuator/metrics

# Prometheus 메트릭
curl http://your-server:8080/actuator/prometheus
```

## 로컬에서 Docker 테스트

배포 전 로컬에서 Docker 이미지를 테스트할 수 있습니다:

```bash
# 프로젝트 루트에서
cd websocket-sse-polling

# Docker 이미지 빌드
docker build -t websocket-sse-polling:local .

# 컨테이너 실행
docker run -d -p 8080:8080 \
  -e SPRING_PROFILES_ACTIVE=local \
  --name websocket-sse-polling-test \
  websocket-sse-polling:local

# 로그 확인
docker logs -f websocket-sse-polling-test

# 테스트
curl http://localhost:8080/actuator/health

# 컨테이너 정지 및 삭제
docker stop websocket-sse-polling-test
docker rm websocket-sse-polling-test
```

## 롤백

배포 후 문제가 발생한 경우 롤백:

```bash
# 서버 접속
ssh user@your-server
cd /opt/websocket-sse-polling

# 이전 버전으로 롤백
docker pull your-username/websocket-sse-polling:previous
docker-compose down
docker tag your-username/websocket-sse-polling:previous \
           your-username/websocket-sse-polling:latest
docker-compose up -d
```

## 트러블슈팅

### 배포가 실패하는 경우

1. **GitHub Actions 로그 확인**
   - Actions 탭 → 실패한 워크플로우 클릭 → 로그 확인

2. **서버 연결 확인**
   ```bash
   # 로컬에서 서버 SSH 연결 테스트
   ssh user@your-server
   ```

3. **Docker Hub 로그인 확인**
   ```bash
   # 로컬에서 Docker Hub 로그인 테스트
   echo "your-token" | docker login -u your-username --password-stdin
   ```

### 컨테이너가 시작되지 않는 경우

```bash
# 컨테이너 로그 확인
docker logs websocket-sse-polling

# 컨테이너 상세 정보 확인
docker inspect websocket-sse-polling

# 포트 충돌 확인
sudo lsof -i :8080
```

### Health Check 실패

```bash
# 컨테이너 내부 접속
docker exec -it websocket-sse-polling sh

# 내부에서 health check
wget --spider http://localhost:8080/actuator/health
```

## 모니터링 설정 (선택사항)

### Prometheus + Grafana 설정

```yaml
# docker-compose.yml에 추가
  prometheus:
    image: prom/prometheus
    volumes:
      - ./prometheus.yml:/etc/prometheus/prometheus.yml
    ports:
      - "9090:9090"

  grafana:
    image: grafana/grafana
    ports:
      - "3000:3000"
    depends_on:
      - prometheus
```

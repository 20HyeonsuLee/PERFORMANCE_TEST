## 개요

이 문서는 `websocket-sse-polling` 모듈의 자동 배포 프로세스를 설명합니다.

### 배포 트리거
- **자동 배포**: `main` 브랜치에 push 시 자동으로 배포
- **수동 배포**: GitHub Actions UI에서 수동 실행 가능

### 배포 환경
- **개발 환경 (dev)**: `develop` 브랜치 push 시
- **운영 환경 (prod)**: `main` 브랜치 push 시

## 배포 전략

### 1. Docker 기반 배포 (권장)

```
빌드 → Docker 이미지 생성 → 컨테이너 레지스트리 푸시 → 서버 배포
```

**장점:**

```
빌드 → JAR 파일 생성 → 서버 전송 → 애플리케이션 재시작
```

**장점:**
- 간단한 구조
- 리소스 오버헤드 적음

## GitHub Actions 워크플로우

### 워크플로우 파일 위치
```
.github/workflows/deploy-websocket-sse-polling.yml
```

### 워크플로우 구조

```yaml
name: Deploy WebSocket-SSE-Polling

on:
  push:
    branches:
      - main
      - develop
    paths:
      - 'websocket-sse-polling/**'
      - '.github/workflows/deploy-websocket-sse-polling.yml'
  workflow_dispatch:
    inputs:
      environment:
        description: 'Deployment environment'
        required: true
        type: choice
        options:
          - dev
          - prod

jobs:
  build-and-deploy:
    runs-on: ubuntu-latest
    steps:
      - 체크아웃
      - Java 설정
      - Gradle 빌드
      - 테스트 실행
      - Docker 이미지 빌드
      - 이미지 푸시
      - 서버 배포
```

## 필요한 설정

### 1. GitHub Secrets

다음 secrets를 GitHub 저장소에 등록해야 합니다:

| Secret 이름 | 설명 | 예시 |
|------------|------|------|
| `DOCKER_HUB_USERNAME` | Docker Hub 사용자명 | `myusername` |
| `DOCKER_HUB_TOKEN` | Docker Hub 액세스 토큰 | `dckr_pat_xxxxx` |
| `SERVER_HOST` | 배포 대상 서버 IP/도메인 | `123.456.789.0` |
| `SERVER_USER` | SSH 접속 사용자명 | `ubuntu` |
| `SSH_PRIVATE_KEY` | SSH 개인키 | `-----BEGIN RSA...` |
| `SLACK_WEBHOOK_URL` | (선택) 배포 알림용 Slack Webhook | `https://hooks.slack.com/...` |

### 2. 서버 환경 설정

배포 대상 서버에 필요한 설정:

```bash
# Docker 설치
sudo apt-get update
sudo apt-get install docker.io docker-compose

# Docker 사용자 권한 설정
sudo usermod -aG docker $USER

# 애플리케이션 디렉토리 생성
mkdir -p /opt/websocket-sse-polling
```

### 3. 환경 변수 파일

서버에 `.env` 파일 생성:

```bash
# /opt/websocket-sse-polling/.env
SPRING_PROFILES_ACTIVE=prod
SERVER_PORT=8080
LOG_LEVEL=INFO
```

## 배포 단계

### 1. 코드 체크아웃 및 빌드

```yaml
- name: Checkout code
  uses: actions/checkout@v4

- name: Set up JDK 21
  uses: actions/setup-java@v4
  with:
    java-version: '21'
    distribution: 'temurin'

- name: Build with Gradle
  run: |
    ./gradlew :websocket-sse-polling:build -x test
```

### 2. 테스트 실행

```yaml
- name: Run tests
  run: |
    ./gradlew :websocket-sse-polling:test
```

### 3. Docker 이미지 빌드

```yaml
- name: Build Docker image
  run: |
    cd websocket-sse-polling
    docker build -t ${{ secrets.DOCKER_HUB_USERNAME }}/websocket-sse-polling:${{ github.sha }} .
    docker tag ${{ secrets.DOCKER_HUB_USERNAME }}/websocket-sse-polling:${{ github.sha }} \
               ${{ secrets.DOCKER_HUB_USERNAME }}/websocket-sse-polling:latest
```

### 4. 이미지 푸시

```yaml
- name: Push to Docker Hub
  run: |
    echo ${{ secrets.DOCKER_HUB_TOKEN }} | docker login -u ${{ secrets.DOCKER_HUB_USERNAME }} --password-stdin
    docker push ${{ secrets.DOCKER_HUB_USERNAME }}/websocket-sse-polling:${{ github.sha }}
    docker push ${{ secrets.DOCKER_HUB_USERNAME }}/websocket-sse-polling:latest
```

### 5. 서버 배포

```yaml
- name: Deploy to server
  uses: appleboy/ssh-action@master
  with:
    host: ${{ secrets.SERVER_HOST }}
    username: ${{ secrets.SERVER_USER }}
    key: ${{ secrets.SSH_PRIVATE_KEY }}
    script: |
      cd /opt/websocket-sse-polling
      docker pull ${{ secrets.DOCKER_HUB_USERNAME }}/websocket-sse-polling:latest
      docker-compose down
      docker-compose up -d
      docker system prune -f
```

### 6. 헬스 체크

```yaml
- name: Health check
  run: |
    for i in {1..30}; do
      if curl -f http://${{ secrets.SERVER_HOST }}:8080/actuator/health; then
        echo "Health check passed"
        exit 0
      fi
      echo "Waiting for service to be healthy... ($i/30)"
      sleep 10
    done
    echo "Health check failed"
    exit 1
```

## 롤백 전략

### 자동 롤백

헬스 체크 실패 시 자동으로 이전 버전으로 롤백:

```yaml
- name: Rollback on failure
  if: failure()
  uses: appleboy/ssh-action@master
  with:
    host: ${{ secrets.SERVER_HOST }}
    username: ${{ secrets.SERVER_USER }}
    key: ${{ secrets.SSH_PRIVATE_KEY }}
    script: |
      cd /opt/websocket-sse-polling
      docker-compose down
      docker pull ${{ secrets.DOCKER_HUB_USERNAME }}/websocket-sse-polling:previous
      docker tag ${{ secrets.DOCKER_HUB_USERNAME }}/websocket-sse-polling:previous \
                 ${{ secrets.DOCKER_HUB_USERNAME }}/websocket-sse-polling:latest
      docker-compose up -d
```

### 수동 롤백

특정 버전으로 롤백:

```bash
# 서버 접속
ssh user@server

# 특정 커밋 해시의 이미지로 롤백
cd /opt/websocket-sse-polling
docker pull username/websocket-sse-polling:<commit-sha>
docker-compose down
docker tag username/websocket-sse-polling:<commit-sha> \
           username/websocket-sse-polling:latest
docker-compose up -d
```

## 배포 알림

배포 성공/실패 시 Slack 알림 설정:

```yaml
- name: Notify Slack on success
  if: success()

  with:
    status: success

  if: failure()
  uses: 8398a7/action-slack@v3
  with:
    status: failure
    text: 'WebSocket-SSE-Polling 배포 실패'
    webhook_url: ${{ secrets.SLACK_WEBHOOK_URL }}
```

## 트러블슈팅

### 배포 실패 시 체크리스트

1. **빌드 실패**
   - Gradle 캐시 확인
   - 의존성 버전 확인
   - Java 버전 확인

2. **테스트 실패**
   - Docker 실행 확인 (Testcontainers 사용 시)
   - 테스트 환경 변수 확인

3. **Docker 이미지 푸시 실패**
   - Docker Hub 자격 증명 확인
   - 네트워크 연결 확인

4. **서버 배포 실패**
   - SSH 연결 확인
   - 서버 디스크 용량 확인
   - 포트 충돌 확인

5. **헬스 체크 실패**
   - 컨테이너 로그 확인: `docker logs websocket-sse-polling`
   - 포트 바인딩 확인: `docker ps`
   - 서버 방화벽 설정 확인
